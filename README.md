# 字节桌面 · ByteDesk

记录代码，也记录灵感。A home for code and ideas.

一个采用 macOS 桌面风格的个人博客，使用 Astro、Vue 3 和 TypeScript 构建。文章在构建时生成静态 HTML，窗口、地图和实验由 Vue 提供交互，照片与壁纸素材托管在 Cloudflare R2。

线上网站：[中文](https://haoqianglyu.com/zh/) · [English](https://haoqianglyu.com/en/)。网站部署到 Cloudflare Workers Static Assets，图片和壁纸通过 `img.haoqianglyu.com` 从 R2 加载。仓库附带 6 篇中英文示例文章，示例图片和旅行地点不代表作者的真实经历。

## 功能

- 可拖动、缩放、收起和全屏阅读的桌面窗口，支持手机布局。
- 中英文、浅色/深色/跟随系统、全站搜索、分类和标签。
- Markdown 文章、目录、代码高亮与复制、图片查看、RSS 和 sitemap。
- Waline 文章评论：游客留言默认直接显示，中英文共用评论，支持管理后台和邮件通知。
- 旅行地图、地点聚合、同地点多篇游记、图片加载失败重试。
- 实验室、项目展示、Zoji 应用截图与交互式手机模型。
- 实验室「报告拆分台」：选择单个、多个 PDF 或文件夹，默认智能识别同一 PDF 中不同页数的报告，也可切换为统一页数（初始 2 页），再按报告编号命名并下载 ZIP；扫描识别在浏览器本地完成。
- 太阳系、地球日夜景和篝火动态壁纸，支持暂停与减少动态效果。

## 启动

使用 Node.js 24.x 和 npm 11 或更新版本。安装了 nvm 时可先执行 `nvm use`。

```sh
npm ci
npm run dev
```

打开终端显示的地址，默认入口为 [中文首页](http://127.0.0.1:4321/zh/) 和 [英文首页](http://127.0.0.1:4321/en/)。

```sh
npm run verify   # 类型检查、生产构建、测试
npm run preview  # 预览 dist，先运行 build
```

依赖版本由 `package-lock.json` 固定；`.npmrc` 使用 npm 官方下载源。当前文章使用 `.md` 文件，尚未接入 MDX。

### PDF 报告拆分

入口为 `/zh/lab/pdf-reports/`（英文 `/en/lab/pdf-reports/`）。默认使用智能识别，按连续报告编号分组。切换到“统一页数”时初始为每 2 页一份，也可设置 4 页或其他 1–1,000 之间的整数；例如每 4 页按 1–4、5–8 页分组，逐页读取右上角的报告编号并核对；无法识别、字符纠正或组内编号不一致时，需在原图旁核对并确认。末尾不足一份的页面会一起保留并提示核对。相同输出文件名追加 `_2`、`_3`，ZIP 仅包含拆分后的 PDF，来源文件和原页码可在页面中核对。

“智能识别（支持混合页数）”模式默认按连续报告编号分组：同一源文件中，连续相同编号的页面放进一个 PDF，编号变化时开始下一份，支持混合 2、4、6 页等长度。印刷的“共几页、第几页”仅供核对，不决定分组；即使连续四页均印着“共 1 页，第 1 页”，或重复两遍“第 1、2 页”，只要编号相同就保留为一份四页 PDF。重复扫描的副本也完整保留。隔着其他报告再次出现的相同编号、不同源文件的同编号报告分别输出，重名时添加后缀。

编号缺失、低置信度或经过字符纠正的页段需要核对边界。夹在相同编号之间的未识别页面可暂归同一段，但仍需确认；位于不同编号之间的未知页面单独保留，不能自动猜测归属。印刷页码准确且需要按页码周期拆出副本时，可在文件设置中改选“按印刷页码”，其页码缺失、冲突、错序或缺页会标为待核对。

文件列表汇总各类页数及份数。每个文件可以覆盖为统一 2、4、6 页或自定义页数，也可选择“手动划分页段”：每行一份，例如 `1-2`、`3-6`、`7-12`；页段必须按顺序覆盖源文件全部页面，不能遗漏、重叠或越界。修改复用已识别页面，点击“应用页段”后生效，尚未应用的设置会阻止下载。报告结果只展示编号原图，并标注其在源文件中的页码，页段确认与编号确认相互独立，均核对完成后方可下载。

当前 OCR 针对此类检测报告的右上角字段及 `E030E10212600001` 这样的编号格式（此处为示例），支持旋转扫描；其他版式可手动填写编号。每批最多 100 个文件、200 MB，单文件最多 100 MB、1,000 页。加密或损坏文件会单独报错，下载部分结果前需要明确选择。

PDF.js、Tesseract.js、英文编号与中文页码识别模型均由本站提供，不向第三方上传 PDF。`predev` / `prebuild` 自动从 npm 依赖准备 `public/vendor/pdf-tools-v1/`，该生成目录不提交；升级依赖时需要同步递增资源路径版本。用户文件、试拆结果和临时识别图片放在已忽略的 `output/`、`tmp/`，不进入网站构建。

开发预览会在启动时预构建 PDF、OCR 和 ZIP 依赖，避免首次点击拆分才发现依赖并触发整页刷新。准备识别资源时只写入有变化的文件，重复构建不会因重写相同资源而清空当前选择。

## 配置

需要自定义时复制 `.env.example` 为 `.env`：

| 变量 | 用途 |
| --- | --- |
| `SITE_URL` | 网站完整地址；默认是本地预览。正式构建设置真实 HTTPS 域名。 |
| `PUBLIC_IMAGE_BASE_URL` | 照片、应用截图与地球/篝火壁纸共用的公开图片地址。默认使用 `https://img.haoqianglyu.com`。 |
| `PUBLIC_WALINE_SERVER_URL` | 可选，覆盖默认的 `https://comments.haoqianglyu.com`；数据库与邮件密钥仅保存在后端。 |

`PUBLIC_` 变量会出现在浏览器端，不能用于保存密钥。项目无需 R2 写入凭据即可本地构建；上传图片时单独管理凭据。本地 `.env`、`.dev.vars`、依赖、构建产物及运行缓存已加入 `.gitignore`。

以本地 HTTP/回环地址、`*.workers.dev` 或 `*.pages.dev` 作为 `SITE_URL` 构建时，不生成可索引页面；正式域名构建启用 canonical 与 robots。通过其他入口访问同一份正式构建时，canonical 仍指向正式域名。示例文章和缺少译文的回退页始终保持 noindex。

## 项目结构

```text
src/pages/          页面、双语路由、RSS、sitemap
src/components/     Vue 交互和页面组件
src/content/posts/  中英文 Markdown 文章
src/lib/            内容、地图、窗口和 Three.js 场景
src/data/           世界地图矢量数据
src/styles/         样式
public/             SVG 标志和 favicon
tests/             几何、路由、图片、SEO 等检查
```
